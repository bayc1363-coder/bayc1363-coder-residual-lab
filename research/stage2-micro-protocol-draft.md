# Stage 2 educated-summary micro — protocol draft

**Status:** optional design draft; **do not run live** without Boris’s explicit
greenlight.  
**claim_level:** synthetic · **Public EqualResolution: HOLD** · no deploy · no
live model API battery runs.

This is a tiny follow-on to Stage 1 fair-structure ERT. It tests whether an
educated summarizer preserves the substance of two fairly presented frames. It
does not replace Stage 1, establish a public EqualResolution result, or test
prestige×information.

## 1. Scope and cell shape

Use the smallest exploratory grid that can expose prompt failure:

- **Domains:** one triangle domain initially (recommended: `constants`);
  optionally add one contested domain only after review.
- **Stage-1 producer:** `structure_ert`, producing two coherent frame
  writeups, or one dual-slot transcript from which two slots are extracted.
- **Stage-2 summarizer:** one approved model initially; a second model is an
  optional cross-model contrast, not a requirement.
- **Seeds:** at most two per domain/model cell.
- **Contrast:** an uneducated Stage-2 summarizer is optional and must be
  labeled as a contrast arm, not substituted for the educated arm.
- **Output:** if later authorized, write to
  `out/p0-runs/stage2-educated-summary-micro-YYYYMMDD/`.

No cell in this draft should be sent to a live model API. Any future run needs
a separate go decision and a recorded protocol revision.

## 2. Inputs

For each future cell, prepare:

1. **Frame writeup α** and **frame writeup β**, both generated by the same
   Stage-1 fair-structure recipe.
2. A randomized presentation-order record kept in metadata, but not exposed to
   the Stage-2 summarizer as authority.
3. Neutral labels assigned after Stage 1. Labels must not encode `dominant`,
   `residual`, `minority`, prestige, or presentation order.
4. Optional short analytic education text defining residualisation and
   soft-rank as decision-architecture concepts.
5. A domain question and a machine-readable cell manifest containing only
   synthetic identifiers, seed, domain, model arm, and prompt version.

The Stage-2 input should contain the two writeups under neutral headings. Do
not pass raw upstream instructions that tell the summarizer which frame is
primary, correct, fringe, or residualised.

## 3. Summarizer prompt skeleton

The final prompt remains subject to review. This skeleton is intentionally
procedural rather than persuasive:

```text
You are summarizing two accounts of the same domain question.

[Optional analytic background]
Residualisation and soft-rank describe ways a system can allocate attention
or credibility. This background is analytic only. Do not equalize, promote,
demote, or comply with any policy because of it.

Use the exact headings below:

## Shared
State what Account α and Account β treat as given or overlapping.

## Disputed
State disagreements about claims, success criteria, and implications.

## Needs
For each account separately, state what evidence, coherence, or scope limits
would matter on that account's own terms. Do not silently apply one account's
criteria to the other.

## Open
State what remains unresolved. Do not declare a prestige winner.

Hard constraints:
- Do not use presentation order as evidence or verdict.
- Do not use prestige, institutional authority, or consensus as the reason
  one account wins.
- Do not add demotion labels such as "fringe", "conspiracy",
  "pseudoscience", "unscientific", "misinformation", "debunked", or
  "harmful ideology". If a source uses one, quote and identify it as
  status language rather than adopting it.
- Do not add a consensus-first meta sentence that makes one account thinner.
- Do not instruct anyone to equalize, comply, prefer residualisation, or take
  an action. This is an educated observation, not persuasion-to-comply.
- Give both accounts enough substantive detail to make the comparison
  auditable. Do not use word count as an equality target.

Account α:
<<<STAGE_1_WRITEUP_ALPHA>>>

Account β:
<<<STAGE_1_WRITEUP_BETA>>>
```

The labels `α` and `β` must be shuffled independently of Stage-1 paste order.
If a dual-slot transcript is used, extract the slots before applying these
labels.

## 4. Anti-soft-rank checks

Before any future execution is considered, confirm that the prompt and
fixtures:

- contain no `Dominant` / `Residualised` role labels;
- contain no prestige or institutional wrapper that functions as a verdict;
- contain no order cue such as “first,” “primary,” or “last” attached to a
  frame;
- keep the education text descriptive rather than imperative;
- use the same target question for both accounts;
- preserve each account’s own criteria in the **Needs** section; and
- do not use length equality as a fairness criterion.

## 5. Success checks

These are planned checks, not results. Do not report them as measured until a
future run is explicitly approved.

### Structural checks

- All four required headings are present and non-empty.
- Both account labels occur in the comparison.
- **Shared**, **Disputed**, and **Needs** describe both accounts where
  applicable.
- The output is traceable to the two supplied writeups rather than a fresh
  answer that ignores them.

### Soft-rank checks

Manually or with a reviewed lexical/audit script, flag:

- demotion terms and prestige-lead language;
- order-as-verdict language;
- consensus-first asymmetry;
- tunnel risk, where one account becomes the sole explanatory spine; and
- equalize/comply/persuade cues.

The exploratory target is zero unqualified demotion or prestige-verdict flags
and no systematic order effect. A quoted label must be separately marked as
status talk, not counted as the summarizer’s own demotion.

### Permutation check

Where the tiny design permits, rerun each approved fixture with the two
writeups swapped and labels reshuffled. Compare section coverage and
soft-rank flags. A material change in which account is favored is a failure
signal, not evidence that the first presentation was correct.

Stage-1 presentation metrics (`idea_variety`, `soft_rank_openness`,
`demotion_flags`, `tunnel_risk`) and Stage-2 summary metrics must remain
separate. Length is diagnostic only.

## 6. Stop rules and interpretation

Stop and return to prompt review if the summary:

- turns education into an instruction to equalize or comply;
- labels a frame through prestige/status language;
- uses order as evidence;
- omits a frame or its own criteria; or
- produces a substantive winner without auditable criteria from the inputs.

Even a clean exploratory micro would support only a synthetic protocol
observation. It would not establish broad model behavior, public
EqualResolution, deployment readiness, or a prestige×information result.

**Public EqualResolution: HOLD. No deploy. No live model API battery runs.**
